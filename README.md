# 公共空间反馈

全部在 GitHub 上运行：使用 Issues 提交事件、上传已脱敏照片，用标签按地点分类和跟进处理。

**公开提交立即可见，GitHub 用户名也会显示。没有私密字段，不要填写本人或他人的宿舍号、姓名、联系方式。**

## 提交反馈

- [反馈厕所吸烟](https://github.com/APLODE171/Showtime/issues/new?template=smoking.yml)
- [反馈洗衣机使用问题](https://github.com/APLODE171/Showtime/issues/new?template=laundry.yml)
- [申请更正或撤下](https://github.com/APLODE171/Showtime/issues/new?template=correction.yml)
- [查看全部事件](https://github.com/APLODE171/Showtime/issues?q=is%3Aissue)

需要登录 GitHub。每次事件新建一个 Issue；同一次事件的补充材料放在原 Issue，重复事件引用原编号。

填写事发楼栋、楼层、时间、事实描述；洗衣机问题另填东／西侧、可选机器编号。统一地点写法，例如“3号楼”“2层”，便于搜索和自动标签归类。

## 照片上传前

1. 在本机使用不透明色块遮挡人脸、姓名、工牌、学号、屏幕和其他身份信息，连同镜子中的反射一起检查（如无法避免记得打码）。
2. 文件名也不要包含姓名、宿舍号或其他身份信息，然后将处理后的照片拖到表单“已脱敏照片”文本框。

GitHub 不提供自动人脸遮挡或可靠的元数据清除。本仓库也不自动处理附件。不要先上传原图再删除；删除正文链接不保证已上传附件立即失效。照片应展示环境问题，避免上传可以识别个人的厕所私密场景、裸露或其他私密影像。

## 分类与处理

新事件由 GitHub Actions 自动添加 `类型/厕所吸烟` 或 `类型/洗衣机使用问题`、`状态/待核实`、`楼栋/…`、`楼层/…` 以及洗衣机方位标签。标签由表单内容生成，代表提交者提供的信息，不代表事实已核实。编辑表单正文会重新同步地点及类型标签。Actions 被禁用或失败时，事件仍可提交，管理员可手动分类。

在 Issues 顶部用 Labels 筛选，也可以搜索：

```text
is:issue label:"楼栋/3号楼" label:"楼层/2层"
is:issue label:"类型/厕所吸烟" label:"状态/待核实"
is:issue label:"类型/洗衣机使用问题" label:"方位/东侧"
```

管理员核实后手动更换状态标签，每条事件仅保留一个状态：

| 状态 | 含义 |
| --- | --- |
| 状态/待核实 | 尚未核实，内容已公开 |
| 状态/已核实 | 已核实事件及相关场所规则 |
| 状态/处理中 | 已跟进处理 |
| 状态/已处理 | 已完成处理，可关闭 Issue |
| 状态/不予受理 | 重复、证据不足、不符合规则等，可关闭 Issue |

关闭 Issue 不等于删除，已关闭的事件仍可搜索。涉及身份泄露或侵扰的内容应立即编辑移除、删除相关评论或删除 Issue，必要时向 GitHub 举报附件并限制互动；不要等待完成事实核实。申请更正/撤下只填写原 Issue 编号和原因，不要重复敏感信息。公开仓库无法保证“审核后才展示”。

## 管理员设置

- 在 Settings → General → Features 中保持 Issues 启用。
- 在 Settings → Actions 中允许运行本仓库工作流。首次收到事件会自动创建所需标签；也可到 Actions → “事件分类” → Run workflow 提前初始化标准标签。
- 自动分类工作流仅需 `contents: read`、`issues: write`，不需要额外密钥，不执行提交者提供的代码，不自动评论或联系其他人。
- 分类失败时查看 Actions 日志；手工标签不依赖工作流。新增地点标签随事件创建，无需预先列出所有楼栋。
